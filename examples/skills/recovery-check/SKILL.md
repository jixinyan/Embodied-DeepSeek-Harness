# Recovery check format

This authored format example illustrates advisory planning and verification content.
Its metadata is marked `test_fixture`; no recovery experiment produced this document.

## When to use

A placement goal remains unverified after an attempt and the current evidence needs review.

## Failure signals

The current authorized containment check is false or the intended object identity is
unresolved. An unknown check does not establish a failed physical condition.

## Possible causes

Object binding or the interpretation of containment may require examination. Current
evidence must establish a cause before it is recorded as an observed explanation.

## Avoid

Do not infer containment from proximity in one image or change the admitted success
conditions to match an observation.

## Planning guidance

Before changing the instruction, compare the intended object binding with
what the latest evidence identifies. Ask for a new observation when identity
is ambiguous; the decision owner selects any retry or replan.

## Verification guidance

Check the task's actual containment predicate using evidence from the stopped
attempt. Do not infer containment from proximity in one camera frame.

## Limits

No robot, simulator or policy run produced this example. It provides neither
motion instructions nor evidence of cross-environment generalization. Never add
conditions to the authoritative task.
